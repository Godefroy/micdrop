# Real-Time Speech to Text in Node.js and TypeScript

To transcribe what a user says in a web app, without a voice agent, give the
Micdrop server a speech to text and nothing else. Each sentence then reaches the
browser as text, over the same WebSocket a voice call uses. `agent` and `tts`
are both optional. Each combination gives a different kind of call, with the same
microphone, [voice activity detection](../client/vad) and transport underneath.

| Configuration       | What the user gets                                            |
| ------------------- | ------------------------------------------------------------- |
| `stt + agent + tts` | A full spoken conversation                                     |
| `stt + agent`       | An assistant that answers in writing                           |
| `stt`               | Dictation, with nothing answering back                         |
| `stt + tts`         | A call your own code drives, speaking when it decides to       |

## Dictation

With a speech to text alone, the server transcribes and stays quiet. Each sentence
reaches the client as a message, exactly as a user message does in a full
conversation.

```typescript
import { MicdropServer } from '@micdrop/server'
import { GladiaSTT } from '@micdrop/gladia'

new MicdropServer(socket, {
  stt: new GladiaSTT({ apiKey: process.env.GLADIA_API_KEY }),
})
```

Any [speech to text provider Micdrop supports](../providers) fits in place of
Gladia, hosted or running in your own Node process. To set up the server and the
client from scratch, [start a first Micdrop call](../getting-started), then
leave out its agent and its voice.

The client displays each sentence from `conversation`, like any other message:

```typescript
Micdrop.on('StateChange', (state) => {
  const text = state.conversation
    .filter((message) => message.role === 'user')
    .map((message) => message.content)
    .join(' ')
  textarea.value = text
})
```

Each sentence appears once the speech to text has finalized it, so the text grows
sentence by sentence, at the pauses. Each provider uses its own signal to end a
sentence. You can follow how
[real-time transcription travels over a WebSocket](/blog/real-time-transcription-websocket-typescript),
from the microphone to the text.

You can run this
[dictation in a complete page](https://github.com/Godefroy/micdrop/tree/main/examples/dictation),
with a microphone button, a language picker and a text area.

Chrome and Safari each ship a recogniser of their own. You can
[compare their speech to text in JavaScript](/blog/web-speech-api) with a
dictation server like this one.

## An assistant that writes instead of speaking

Without a text to speech, the agent still answers, as a message sent to the
client. Nothing is synthesized, so nothing plays.

```typescript
new MicdropServer(socket, {
  stt,
  agent: new OpenaiAgent({
    apiKey: process.env.OPENAI_API_KEY,
    systemPrompt: 'You are a helpful assistant',
  }),
})
```

The client leaves its processing state as soon as the answer is complete, and
`isAssistantSpeaking` stays false for the whole call, since no voice ever plays.

Turn on [`partialMessages`](./partial-messages) to stream the answer as it is
written, which is what makes a text answer feel as immediate as a spoken one.

## Driving the conversation yourself

A call with a voice and no agent speaks only when your code asks it to. Use this
setup when the answers come from a state machine, a workflow
engine, or an orchestration framework you already run.

```typescript
const server = new MicdropServer(socket, { stt, tts })

server.on('Message', async (message) => {
  if (message.role !== 'user') return
  const answer = await myOwnOrchestrator(message.content)
  server.speak(answer)
})
```

`speak()` accepts a string or a stream of text. Given a string, it also records
the sentence in the conversation, since no agent is there to do it.

## Reading the conversation

`server.conversation` holds everything said, whether an agent keeps it or the
server does, and stays readable once the call is over.

```typescript
const server = new MicdropServer(socket, { stt })

server.on('End', ({ conversation, duration }) => {
  console.log(`${conversation.length} sentences in ${duration}s`)
})
```

The `Message` event fires for every message added on either side, so you can
[save the messages](./save-messages) as they arrive.

<Callout type="info">
  With an agent, the conversation opens with the system message that carries the
  prompt. Without one, it holds only what was said.
</Callout>

## What still needs an agent

`generateFirstMessage` asks the agent for its opening line, so it does nothing
without one. A static `firstMessage` works either way, and is spoken when a text
to speech is configured.

Tools, [automatic call ending](./auto-end-call),
[extraction](./extract) and [semantic turn detection](./semantic-turn-detection)
are agent features, and are out of reach in a call that has no agent.

## FAQ

<FaqList>
  <FaqItem question="What does the client receive during dictation?">
    Each sentence the speech to text finalizes arrives as a message with the
    `user` role in `conversation`, the same list a full conversation fills. The
    text grows sentence by sentence, whenever the speaker pauses. The server
    sends back text only.
  </FaqItem>
  <FaqItem question="Do I need an AI agent to transcribe speech?">
    A speech to text is all the server requires. With `stt` alone, the server
    transcribes and stays quiet. An agent becomes necessary for tools,
    `generateFirstMessage`, extraction, automatic call ending and semantic turn
    detection.
  </FaqItem>
  <FaqItem question="How much does real-time transcription cost?">
    Micdrop itself is open source under the MIT license, so you pay only the
    speech to text provider. An hour of audio costs $0.36 with OpenAI, $0.62
    with Gradium and $0.75 with Gladia, at the list prices of their entry paid
    plans in August 2026. Mistral Voxtral charges $0.008 a minute, or $0.48 an
    hour. [Whisper running in your Node process](../speech-to-text/whisper) is
    free and keeps the audio on your own server. Providers also differ on
    [latency and languages](../speech-to-text).
  </FaqItem>
</FaqList>
