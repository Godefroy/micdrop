# Client (React Native)

`@micdrop/react-native` runs a Micdrop call on a phone. It records the microphone, plays the assistant voice, detects who is speaking and streams both ways over a WebSocket, against the same [server](/docs/server) a browser talks to.

The server holds the transcription, the agent and the voice, so no speech model ships in the app. [Speech to text in React Native](/blog/speech-to-text-react-native) compares server-side transcription with the iOS and Android recognisers and with running Whisper on the device. The server can also hold a speech-to-speech session, which is how a phone [reaches the OpenAI Realtime API without WebRTC](/blog/openai-realtime-api-react-native).

## Installation

```bash
npm install @micdrop/react-native @micdrop/react react-native-audio-api
```

Audio goes through native code, so the app runs from a development build rather than from Expo Go. See [Installation](./installation) for the permissions and the config plugin.

## Quick start

```tsx
import { useMicdropState } from '@micdrop/react'
import { Micdrop } from '@micdrop/react-native'
import { Button, Text, View } from 'react-native'

export default function Call() {
  const state = useMicdropState()

  const handlePress = () =>
    state.isStarted
      ? Micdrop.stop()
      : Micdrop.start({ url: 'wss://example.com/call' })

  return (
    <View>
      <Text>{state.isUserSpeaking ? 'Listening' : 'Your turn'}</Text>
      <Button
        title={state.isStarted ? 'Hang up' : 'Start the call'}
        onPress={handlePress}
      />
    </View>
  )
}
```

`Micdrop.start()` asks for the microphone permission, configures the audio session for a call, opens the connection and starts listening. The rest of the app only reads the state.

## What you get

- Microphone capture at 16 kHz, and playback of the answer as it streams in
- [Voice activity detection](./vad), on volume or with the Silero model, so the user just talks
- Interruption: the assistant stops the moment the user starts speaking
- Mute, pause, and a choice between the loudspeaker and the earpiece
- Reconnection when the network drops
- React hooks for the whole [call state](./hooks)

## Same API as the browser

Running a call is the very same code as in a browser, `@micdrop/client`, which this package and [@micdrop/web](/docs/client) both build on. The pages of the browser section apply here as they are written, only the import changes:

- [Start and stop a call](/docs/client/start-stop-call), [mute](/docs/client/mute-unmute-call) and [pause](/docs/client/pause-resume-call)
- [Call state](/docs/client/call-state) and the [React hooks](/docs/client/react-hooks) that read it
- [The conversation](/docs/client/display-conversation-messages), [tool calls](/docs/client/handling-tool-calls) and [error handling](/docs/client/error-handling)
- [Voice activity detection](/docs/client/vad) and [turn detection](/docs/client/turn-detection), options and events included
- [Reducing latency](/docs/client/latency)

What the hardware underneath changes:

- Output is a route rather than a device, see [Audio output and devices](./audio-output)
- The audio session is configured as a phone call, which is what turns on echo cancellation
- Silero and the turn detector run on the native ONNX runtime, which takes a patch, see [Installation](./installation#the-onnx-runtime)
- Settings are remembered only once the app installs a store, see [Voice activity detection](./vad)
